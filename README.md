# ocd-app

## Introduction

__ocd-app__ is an example of how to integrate [ora* CODEDOC](https://github.com/yerba1704/ocd) into [APEX](https://www.oracle.com/apex/) and [ORDS](https://www.oracle.com/database/technologies/appdev/rest.html): an APEX application and a REST service to browse the technical documentation of PL/SQL packages.
It is an __ora* CODEDOC publisher (OCDp)__ and renders the JSON output of `ocd.api.information` in a format similar to Oracle’s [Database PL/SQL Packages](https://docs.oracle.com/en/database/oracle/oracle-database/26/arpls/) reference.

- __Live demo__: https://sf0e2zmteguh3bs-hoh.adb.eu-frankfurt-1.oraclecloudapps.com/ords/r/ocd/ocd_apex_public/
- __Download__: [latest release](https://github.com/markushohloch/ocd-app/releases/latest) or clone this repository

The application consists of four pages:

- __Package Browser__ lists all packages of the selected schemas, including their description, and can be filtered by name or description.

- __Package Details__ shows the full documentation of a single package: description, constants, subtypes, types, exceptions, a summary of all subprograms and for each subprogram the syntax, parameters and examples. Syntax and examples can be copied with a single click.

- __Schemas__ lets signed in users select the schemas whose packages are listed and inspected. The selection is stored in the table `OCD_APEX_SCHEMA` and applies to all users; schemas maintained by Oracle cannot be selected.

The formatting options of the [ora* CODEDOC syntax (OCDs)](https://github.com/yerba1704/ocd/blob/main/doc/ocds.md) are supported: highlighting with backticks, paragraphs, hyperlinks (with an optional short name in square brackets) and references to other packages or components in double square brackets.

```plsql
-- For more information see [[API.INFORMATION]] or https://github.com/yerba1704/ocd[GitHub].
```

## Example usage

The HTML documentation is generated by the function `ocd_apex_util.package_html`, so it can be used outside the application too:

```sql
select ocd_apex_util.package_html('YOUR_PACKAGE_NAME', 'YOUR_SCHEMA') from dual;
```

:information_source: Links to other packages point to the details page of the application and are only valid within an APEX session.

## REST service

Besides the APEX application, the documentation is also available as REST service via [ORDS](https://www.oracle.com/database/technologies/appdev/rest.html). The module `ocd.docs` is installed with the script `database/ords/ocd_docs.sql` and provides two endpoints:

| Endpoint | Result |
| --- | --- |
| `GET .../ords/<schema-alias>/docs/packages/` | All packages of the selected schemas with schema, name and description |
| `GET .../ords/<schema-alias>/docs/packages/:name` | The JSON output of `ocd.api.information` for a single package (`404` if the package does not exist); the optional parameter `schema` selects the schema, default is `OCD` |

Examples from the live demo:

- All packages: https://sf0e2zmteguh3bs-hoh.adb.eu-frankfurt-1.oraclecloudapps.com/ords/ocd/docs/packages/
- Package `PKG_SAMPLE` of schema `OCD_DEMO`: https://sf0e2zmteguh3bs-hoh.adb.eu-frankfurt-1.oraclecloudapps.com/ords/ocd/docs/packages/pkg_sample?schema=ocd_demo

```shell
curl https://<host>/ords/ocd/docs/packages/pkg_sample?schema=ocd_demo
```

:information_source: Both endpoints can be read without authentication. The `OCD` schema must be REST enabled (`ords.enable_schema`).

## Installation

__ora* CODEDOC__ must be installed first. All objects of __ocd-app__ are installed in the `OCD` schema.

1. create the database objects (table `ocd_apex_schema`, views and package `ocd_apex_util`) with [SQLcl](https://www.oracle.com/database/sqldeveloper/technologies/sqlcl/) connected as `OCD`:

```sql
cd database
@install.sql
```

2. import the application with SQLcl into an APEX workspace that uses the `OCD` schema:

```sql
apex import -input ./apex
```

3. select the schemas on the page __Schemas__ (initially only `OCD`) and analyse their packages, e.g. all at once with the button __Inspect all packages__ or:

```plsql
begin
  ocd_apex_util.inspect_all_packages;
end;
```

The application is stored in the [APEXlang](https://docs.oracle.com/en/database/oracle/apex/) format. Use `apex validate -input ./apex` to check it before an import.

:exclamation: The APEXlang parser does not accept Windows line breaks (CRLF). The file `.gitattributes` ensures that git always checks out `*.apx` files with UNIX line breaks (LF).

## Requirements

- [ora* CODEDOC](https://github.com/yerba1704/ocd)
- Oracle APEX 26.1 or above
- SQLcl with APEXlang support (tested with 26.3)
- Oracle Database 19c or above
